# Funny: лексер и LL(1)-парсер (HW1 + HW2)

Парсер использует существующий лексер проекта: регулярные выражения → НКА
Томпсона → ДКА → минимизация → токены. Ветка HW2 — рекурсивный спуск
с одним токеном просмотра, без генераторов и сторонних библиотек во время запуска.

## Сборка и запуск

Нужны JDK 21 и Maven 3.8+. Команды выполняются из `funny-lexer`:

```bash
mvn clean verify
java -cp target/classes funny.ParserMain examples/full.funny
java -cp target/classes funny.ParserMain examples/errors.funny
```

Если системная Java новее, для сборки с JaCoCo 0.8.12 выберите JDK 21:

```bash
JAVA_HOME=/usr/lib/jvm/java-21-openjdk mvn clean verify
```

Исходник можно передать через stdin (без аргументов или с `-`):

```bash
printf 'function f() returns r:int { r = 1 + 2 * 3; }' | java -cp target/classes funny.ParserMain -
java -cp target/classes funny.ParserMain examples/full.funny > ast.json
```

AST в JSON выводится в stdout, сообщения `строка:столбец: описание` — в stderr.
Коды завершения: `0` — успех, `1` — лексическая/синтаксическая ошибка,
`2` — ошибка чтения или аргументов. При синтаксических ошибках выводится частичный
AST; использовать его как корректную программу нельзя. При лексической ошибке
разбор останавливается, AST не выводится.

Старый демонстрационный запуск лексера и экспорт ДКА сохранены:

```bash
java -cp target/classes funny.Main
java -cp target/classes funny.Main target/dfa.json
```

## Пример языка

```text
function change(a:int[], i:int)
requires i >= 0 and i < length(a)
returns b:int[]
ensures b[i] == 42
uses temporary
{
    b = a;
    b[i] = 42;
    if (i == 0) {
        assert b[0] == 42;
    } else {
        assume true;
    }
}
```

Поддерживаются функции с типизированными параметрами и результатами `returns`,
необязательные `requires`, `ensures`, `uses`, `invariant`; присваивания, вызовы,
несколько результатов (`x,y = pair();`), `if`/`else`, `while`, вложенные блоки,
`assert`/`assume`, арифметика, сравнения, логические операции, `length`, чтение
и обновление массивов. Пустое тело функции `{}` допустимо. Пустые условия
`requires`/`ensures` задаются отсутствием соответствующей секции; если ключевое
слово указано, за ним обязательно выражение.

Приоритеты, ассоциативность и объяснение LL(1) находятся в
[docs/LL1.md](docs/LL1.md); полная финальная грамматика —
[docs/grammar.ebnf](docs/grammar.ebnf).

## Файлы и API

| Файл | Назначение |
|---|---|
| `token/TokenSpecs.java` | Регулярные выражения и приоритеты токенов |
| `lexer/Lexer.java` | Существующий DFA-лексер, теперь с позициями |
| `lexer/SourcePosition.java` | Смещение с нуля, строка/столбец с единицы; CRLF — один перевод строки |
| `parser/Parser.java` | Правила грамматики, приоритеты и режим паники |
| `parser/Ast.java` | Неизменяемые records узлов AST |
| `parser/ParseResult.java` | AST и список диагностик; `success()` |
| `parser/AstPrinter.java` | Читаемый JSON без дополнительных зависимостей |
| `ParserMain.java` | Чтение файла/stdin, AST и диагностика |
| `Main.java` | Прежний пример лексера и экспорт автомата |

Пути Java-файлов в таблице относительны к `src/main/java/funny`.

Подключение парсера после создания `Lexer lexer`:

```java
var tokens = lexer.tokenize(source);
var result = new Parser(tokens, SourcePosition.endOf(source)).parse();
System.out.println(AstPrinter.toJson(result.program()));
for (var diagnostic : result.diagnostics()) {
    System.err.println(diagnostic);
}
```

Каждый узел JSON содержит `kind`, поля соответствующего record и `position`:
`{"offset": 0, "line": 1, "column": 1}`. Корень — `Program`, его `functions` —
список `Function`. Отсутствующие предусловие, постусловие, инвариант и ветка else
представляются `null` (семантические значения по умолчанию определяет следующий
этап). `Variable.type` — `int`, `int[]` или `null` для нетипизированной локальной
переменной. Числовые литералы сохраняются строкой без ограничения разрядности.
Полный небольшой эталон — [minimal.json](src/test/resources/parser/minimal.json).

Обновление массива сразу преобразуется в AST функционального копирования:

```text
a[i] = v;    → Assign([a], ArraySet(Name(a), i, v))
a[i][j] = v; → Assign([a], ArraySet(Name(a), i,
                         ArraySet(ArrayRead(Name(a), i), j, v)))
```

`ArraySet` — специальный узел, не обычный вызов пользовательской функции `set`.
`b = a` остаётся обычным Assign: копирование массива при исполнении должен
реализовать следующий этап. Вложенные обновления описывают чистые выражения;
порядок вычисления и временные переменные будут определяться при снижении в IR.

## Соответствие Funny и ограничения подмножества T0/T1

Сверено с [HW02](https://github.com/nsu-fit/TVDSL/blob/main/homeworks/HW02_parsing.md),
[P03](https://github.com/nsu-fit/TVDSL/blob/main/practices/P03_ll1.md) и
[Funny RU](https://github.com/nsu-fit/TVDSL/blob/main/funny.ru.md).
Указанный в задании `docs/funny.ru.md` в текущем репозитории курса отсутствует;
файл находится в корне.

Отклонения и границы реализации:

- Обязательное слово `function` соответствует примеру P03 и существующему
  лексеру; в EBNF полной спецификации Funny это слово пропущено.
- Тела функции, if, else и while обязательно заключаются в `{}`. Это устраняет
  dangling else и сохраняет строгий выбор по одному токену. Для `else if`
  используется `else { if (...) { ... } }`.
- Формулы `=>` и кванторы `forall`/`exists` не входят в выбранное подмножество.
- Выражения и предикаты объединены в одну грамматику. Парсер допускает, например,
  `if (1)`; проверка булевого типа, существования имён, сигнатур вызовов,
  неизменяемости параметров, типов массивов и инициализации — задача HW3.
  По этой же причине вложенные индексы разбираются синтаксически, хотя типы
  базового Funny ограничены `int` и `int[]`.
- Импликация разрешена во всех выражениях, включая предикаты; в спецификации
  она явно приведена только для условий. Цепочки сравнений `a < b < c` запрещены.
- Сохранены идентификаторы HW1 `[A-Za-z_][A-Za-z0-9_]*` (полный Funny описывает
  букву в начале и буквы/цифры далее), ASCII-алфавит и запрет ведущих нулей.
- Восстановление синтаксических ошибок выполняется в режиме паники; лексические
  ошибки останавливают обработку. Глубина рекурсии ограничена стеком JVM.

## Тесты

```bash
mvn test
mvn verify
```

Проверяются существующий лексер и regex, все основные конструкции парсера,
позиции после комментариев/CRLF, приоритеты и ассоциативность, форма обновления
массивов, точное сравнение JSON с эталоном, восстановление после нескольких
ошибок и переход к следующей функции. Дополнительно 300 воспроизводимых
случайных последовательностей проверяются с таймаутом на отсутствие зацикливания.

В `src/test/resources/parser` положительный `minimal.funny` сопровождается
ожидаемым `minimal.json`. Отрицательные примеры `empty`, `unclosed`, `extra`,
`operator`, `missing_semicolon` сопровождаются `.error` с точной первой
диагностикой. `examples/full.funny` — комплексный положительный пример,
`examples/errors.funny` — три ошибки и продолжение разбора.

JaCoCo при `mvn verify` проверяет сохранённый порог покрытия строк 70%; отчёт:
`target/site/jacoco/index.html`.
