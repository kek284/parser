# Почему достаточно одного токена

Выбрана ветка LL(1), без генератора. Итоговые правила находятся в `grammar.ebnf`.
Левая рекурсия выражений заменена циклами: `E -> E + T | T` превращается
в `E -> T { + T }`. Общие префиксы присваиваний и вызова/имени факторизованы.

Основные множества FIRST:

| Нетерминал | FIRST |
|---|---|
| function | FUNCTION |
| block | LBRACE |
| assignment | IDENT |
| conditional | IF |
| loop | WHILE |
| assertion | ASSERT |
| assumption | ASSUME |
| expression | NOT, MINUS, INT, TRUE, FALSE, LPAREN, IDENT, LENGTH |
| assignmentTail | ASSIGN, LBRACKET, COMMA |
| arguments | LPAREN |

Альтернативы statement выбираются по разным токенам FIRST.
После IDENT токены `(`, `[` и операторы различают вызов, индекс и простое имя.
После `int` токен `[` выбирает массив; иначе пустое продолжение типа.
Пустой список параметров выбирается по `)`, непустой — по IDENT.
После параметров requires выбирается по REQUIRES, иначе FOLLOW — RETURNS.
После возвращаемых переменных ensures выбирается по ENSURES, иначе USES или `{`.
После ensures uses выбирается по USES, иначе `{`.
Тела if/else/while обязательно блоки: FOLLOW необязательного else не содержит ELSE,
поэтому конфликта dangling else нет. Это осознанное ограничение относительно Funny.

Приоритеты от слабого к сильному: `->`, `or`, `and`, `not`, сравнения,
`+ -`, `* /`, унарный `-`, индексация/вызов. Импликация правоассоциативна,
арифметика, and/or — левоассоциативны, сравнения неассоциативны.
`not a < b` разбирается как `not (a < b)`.
Скобки общие для арифметики и логики: отдельные альтернативы `condition`/`expr`
не требуют просмотра вперёд или отката. Типы операндов проверяются на следующем этапе.

Восстановление в режиме паники: внутри блока пропускаются токены до `;`, `}`,
EOF, FUNCTION или начала следующего statement. `;` поглощается, `}` остаётся
владельцу блока. FUNCTION позволяет найти следующую функцию даже при потерянной `}`.
В случае ошибки заголовка пропускается всё до FUNCTION/EOF.
При восстановлении без продвижения поглощается хотя бы один ошибочный токен,
либо управление возвращается внешнему правилу на `}`/FUNCTION/EOF.
Таким образом, циклы восстановления всегда продвигаются или завершаются.
Ошибочный оператор/функция не добавляется в AST; успешно разобранные сохраняются.
EOF имеет точную позицию, включая пробелы и комментарии в конце файла.
EOF не добавляется в результат HW1-лексера, а создаётся конструктором Parser.
Пустая программа и лишний ввод диагностируются. Как у обычного рекурсивного
спуска, очень глубокая вложенность ограничена стеком JVM.
